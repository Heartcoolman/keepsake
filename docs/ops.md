# 运维台(/ops)

部署者视角的操作员控制台:管账户、看用量、盘磁盘、控注册。页面由服务端直接托管在 `GET /ops`(与用户端 SPA 完全分离,不进用户 bundle),API 挂在 `/api/ops/*`。

## 权限模型(先读这个)

- **运维台没有任何用户密钥**。照片、日记、聊天、人脸特征、人格画像全部是密文,操作员既看不到也解不开;台面上的一切都是结构元数据(用户名、类型、条目数、磁盘占用、token 计数)。
- **不能重置用户密码**。找回只有用户自己的恢复码(`POST /api/v1/auth/recover`)——这是产品卖点,不是缺陷。
- 操作员能做的破坏性动作:停用/启用账户、**删除独立账户(含全部数据)**、**解散家庭(共享数据永久销毁)**。全部写入审计。

## 操作员账户

- 存储在 `data/ops/<id>.json`,与用户账户体系完全隔离(无密钥字段、独立的 JWT 签名域:HKDF(JWT_SECRET, "nianxiang-ops"),用户令牌与运维令牌互不接受)。
- 令牌 12 小时有效,无刷新,存于浏览器 sessionStorage;登出/改密/删号即时吊销(tokenVersion)。
- **首次引导**:在 `.env` 设 `OPS_BOOTSTRAP_TOKEN=<长随机串>` → 重启 → 打开 `/ops` → 「首次引导」输入令牌+用户名+密码。仅在操作员数为 0 时可用;引导完成后建议从 `.env` 移除令牌。
- 操作员互为对等:可互相建号、重置密码、删除(全部入审计)。
- **唯一操作员丢密码**:部署者 ssh 进服务器删除 `data/ops/` 下的记录文件,引导即重新开放。

## 功能页签

| 页签 | 内容 |
|---|---|
| 概览 | 记录计数、密钥环在线数、磁盘占用分解(60s 缓存,可强制重算)、各账户加密迁移状态、depth/analyze 缓存清理、备份管理 |
| 模型 | 四个模型槽位的生效权重与版本、后端(sidecar/本地 CPU)、会话是否预热;sidecar `/healthz` 探测;`server/models/` 全部权重文件与「未被引用」标记;运行速度滚动统计;基准测试(见下) |
| 账户 | 全部账户结构信息(类型/家庭/条目数/占用/迁移状态/套餐与本月配额使用率);切换套餐(下拉,写审计);停用/启用(即时踢下线并清内存密钥);删除独立账户(硬清除,需输入用户名确认) |
| 家庭 | 家庭与成员;紧急解散(见下) |
| 用量 | AI token 消耗按月汇总与按账户明细;每行可清零该账户当月计数(误判补偿,写审计) |
| 授权 | 当前令牌的 licensee / 版本 / 签发与到期(含剩余天数)、席位占用、可发放套餐、各档配额;到期 30 天内红字告警;未授权时明示降级原因 |
| 注册 | 运行时开关注册、设置/轮换/取消注册码(写入 `data/ops-config.json`,即刻覆盖 `REGISTRATION_CODE` env;注册码不回显) |
| 操作员 | 操作员增删与密码重置 |
| 审计 | `data/ops-audit.jsonl` 尾部(操作员、动作、对象;绝不含密码/注册码明文) |

## 危险操作语义

- **删除账户**:仅限不在家庭中的账户(否则 409)。清除范围:条目+图片+缩略图、记忆/人格、月度回顾、用量计数、analyze/depth 缓存、个人作用域人物/关系/人脸缓存、指向其的邀请、账户记录本体。家庭成员须先由家庭主在应用内移出(那条路径会做 FK 轮换),或整体解散家庭。
- **解散家庭**:无密钥的紧急操作。共享作用域的密文(人物库**含全体成员的人脸建档**、关系图、人脸缓存)随密钥一同作废、直接删除,**无法恢复**;成员回到独立状态,条目重置待重扫,下次登录自动重建空白身份人物并重扫人脸(NAS 上多人同时登录会排队,属预期)。家庭主保留家庭账户类型,可在应用内「创建家庭」重新开始。幂等:中途崩溃后对同一 id 重新调用即可完成收尾。
- **备份**:复制 `data/` + `cache/`(含人脸缓存——它们不可再生,正是要备的)到 `data/backups/<时间戳>/`,在挂载卷内,容器重建不丢;内容本就是密文,备份不降低隐私。对并发写容错(跳过瞬时文件)。**没有恢复接口**:恢复=停服后手工把备份目录覆盖回 `data/`、`data/cache` 并重启。注意备份包含全部照片密文,占用与 data 同量级,记得定期清理。
- **缓存清理**:仅 depth/analyze(纯性能缓存,用户带钥会话内按需重算)。face/faceThumb 不可清——清了会破坏聚类且重扫需要属主登录。

## 部署核对清单

1. `.env` 增加 `OPS_BOOTSTRAP_TOKEN`(`openssl rand -hex 24`),重启服务。
2. 打开 `http://<host>:8787/ops` → 首次引导建操作员。
3. 从 `.env` 移除 `OPS_BOOTSTRAP_TOKEN`(可选但推荐)。
4. 若经反代暴露公网,建议对 `/ops` 与 `/api/ops` 加 IP 白名单——运维台被攻破等于全部账户可被停用/删除(仍读不到内容)。

## 模型页签

- **为什么需要它**:depth 与 matting 都是「先打 sidecar,失败静默回落本地 CPU」。sidecar 挂掉不会报错,只会变慢。这个页签把三件看不见的事变成可见的:跑的是哪个权重文件、走的是哪条路径、各花多少毫秒。
- **速度统计是进程内滚动窗口**:被动采样真实请求,每个指标保留最近 128 次,算 p50/p95;**失败不进分位数**(一次 120s 推理超时会把 p95 埋掉),但单独计失败数。不落盘,重启清零 —— 换模型/换硬件后旧数字本来就没意义。
- **判读回落**:`depth.sidecar` 与 `depth.local` 同时有采样,就是 sidecar 正在失败并回落;matting 同理。
- **基准测试**:合成图(固定公式生成,永不碰用户数据)跑一遍各模型,以 `batch` 优先级入推理队列,不插队真实用户。深度跑两次(两张不同的图,第二次不是缓存命中);人脸识别用合成对齐图直接喂 `w600k_r50` —— 合成图上检不出人脸,不这么做识别模型永远测不到。跑完清掉自己写的缓存。同一时刻只允许一个基准测试(第二个拿 409)。
- **AI provider 探测会发出一次真实计费调用**,但**不计入任何账户用量**(不传 meterId),只在审计里留一行。`MOCK_AI=1` 时跳过。
- **孤儿权重**:页签会标出 `server/models/` 里没有任何代码引用的文件。只打标,不提供删除 —— 删文件请 ssh 上去手动做。matting v1/v2/v3(合计约 141MB)已于 P5 删除,训练 checkpoint 有档案可重新导出(`core/docs/model-archive.md` §6.2);该标记的作用是检出后续再次沉积的死权重。
- **compose 已透传全部推理相关变量**:`DEPTH_SIDECAR_URL`、`MATTING_SIDECAR_URL`、`DEPTH_SIDECAR_TILES`、`INFERENCE_TIMEOUT_MS`、`INFERENCE_DISABLED`、`APP_TZ` 均可从宿主 `.env` 直接设置。仍显示「未配置」即表示宿主 `.env` 里确实为空,而非 compose 拦掉了。代码读取的环境变量集合、`.env.example`、compose 三者的一致性由 `scripts/check-env-parity.sh` 校验。

## 导出功能(分享卡 / 年度回忆册)

- **字体**:约 34MB 的 Noto CJK,不入 git。首次导出时服务自动下载到 `server/assets/fonts/`;要避免这次运行时下载(或主机访问不了 GitHub),部署前在构建主机跑一次 `scripts/fetch-fonts.sh`,`COPY server server` 会把它带进镜像。字体没就位时导出端点返回 503 `UNAVAILABLE`,其余功能不受影响。
- **时区**:卡片与册子的日期标签按 `APP_TZ` 渲染,代码内默认 `Asia/Shanghai`(`annual.ts` 的 `ymdCn` 是唯一日期标签路径,分享卡与年度册共用)。容器时钟是 UTC,但该默认值使不设变量时的行为对 UTC+8 部署已正确;仅当部署在其他时区才需显式设置,否则 08:00 之前的回忆会比 App 里显示的日期早一天。

## 计费与配额

- **两层叠加**:账户的 `plan` 选定配额行;部署的授权令牌限定这个部署**能发放哪些套餐**(`plans` 声明)与**能承载多少账户**(`seats` 声明)。账户记录上存着但令牌不允许的套餐,读取时降级为 `free`——令牌过期或降级不会让任何记忆库失效。
- **各档配额**见「授权」页签,或 [docs/api-v1.md](api-v1.md#plans--quotas)。改配额数值改 `server/src/plans.ts` 一处。
- **新账户的默认套餐随令牌**:有令牌时取令牌允许范围内最宽的一档,无令牌(演示模式)为 `free`。理由:自托管场景下令牌本身就是付费凭据,部署方不该在自己的服务器上落到免费档。要对家庭成员限额,由操作员在账户页签逐个下调。
- **存量账户的祖父条款**:闸门首次上线时,已存在且仍为 `free` 的账户被升到 `family`(marker `data/migration-plan.json`,只跑一次)。闸门上线前所有账户都是不限额且可导年度册的,直接按 `free` 读取等于静默收回已交付的能力。
- **被闸门覆盖的只有 AI 端点**:列表、上传、读取媒体、人物、图谱、分享卡都不计量。额度用尽后记忆库照常读写,只是念念不再开口。
- **年度回忆册是套餐能力而非额度项**:`free` 下返回 `FORBIDDEN`(不是 `QUOTA_EXCEEDED`)。
- **配额是近似上限**:用量计数在 AI 调用返回后异步落盘(`xai.ts` 里的 `void recordUsage`),闸门读的是上一次落盘值,单账户实际消耗最多可超出配额一次调用。个人与家庭规模下这是有意的取舍;要做按 token 精确对账,须先把计量改成同步写入。
- **清零当月计数**是唯一能撤销一次错误拒绝的手段(用量页签每行的「清零」),写入审计。
- **换令牌需重启进程**:`licenseBoot` 是 `index.ts` 的首个 import,并以写 `process.env` 的方式实施降级,没有热更新入口。
